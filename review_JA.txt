Inception 評価シート

このチームでは、学生1名を評価してください。

はじめに

以下のルールを守ってください。

- 評価中は、礼儀正しく、相手を尊重し、建設的に接してください。コミュニティの健全さは、こうした姿勢によって保たれます。

- 評価対象の学生またはグループのプロジェクトについて、不具合の可能性を確認してください。問題が見つかった場合は、時間を取って話し合ってください。

- 課題の指示や機能の範囲について、学生ごとに解釈が異なる可能性を考慮してください。常に柔軟な姿勢で、できる限り公正に採点してください。相互評価は、真剣に取り組んでこそ学びにつながります。

評価の指針

- 評価対象の学生またはグループがGitリポジトリに提出した成果物だけを採点してください。

- Gitリポジトリが評価対象の学生のものであることを再確認してください。対象のプロジェクトが正しいことと、空のディレクトリに対して「git clone」が実行されることも確認してください。

- 公式リポジトリ以外の内容を評価させるための、不正なエイリアスが使われていないか慎重に確認してください。

- 想定外の事態を避けるため、テストや自動化など、採点を補助するスクリプトが使われる場合は、その内容を一緒に確認してください。

- 自分がまだ取り組み終えていない課題を評価する場合は、評価を始める前に課題文をすべて読んでください。

- 空のリポジトリ、動作しないプログラム、Norm違反、不正行為などを報告する際は、用意されたフラグを使ってください。
  これらに該当する場合は評価を終了し、最終評価は0点、不正行為の場合は-42点とします。
  ただし、不正行為を除き、同じ間違いを繰り返さないために、提出内容を学生と一緒に振り返ることを強く勧めます。

一般指示

評価中に要件の確認方法や検証方法が分からない場合は、評価対象の学生に協力してもらってください。

アプリケーションの設定に必要なファイルがすべてsrcsフォルダー内にあることを確認してください。srcsフォルダーはリポジトリのルートに置く必要があります。

リポジトリのルートにMakefileがあることを確認してください。

評価を始める前に、ターミナルで次のコマンドを実行してください。

docker stop $(docker ps -qa); docker rm $(docker ps -qa); docker rmi -f $(docker images -qa); docker volume rm $(docker volume ls -q); docker network rm $(docker network ls -q) 2>/dev/null

docker-compose.ymlを読み、「network: host」や「links:」が含まれていないことを確認してください。含まれている場合は、その時点で評価を終了します。

docker-compose.ymlに「network(s)」の指定があることを確認してください。ない場合は、その時点で評価を終了します。

Makefileと、Dockerを使用するすべてのスクリプトを調べてください。「--link」が含まれている場合は、その時点で評価を終了します。

Dockerfileを確認してください。ENTRYPOINTに「tail -f」や、バックグラウンドで実行するコマンドがある場合は、その時点で評価を終了します。
また、スクリプトを実行する目的以外で「bash」や「sh」を使っている場合も同様です。例：「nginx & bash」「bash」。

コンテナが、AlpineまたはDebianの最新の安定版の1つ前のバージョンをベースにビルドされていることを確認してください。

entrypointがスクリプトの場合、プログラムをバックグラウンドで実行していないことを確認してください。
スクリプト形式の例：ENTRYPOINT ["sh", "my_entrypoint.sh"]、ENTRYPOINT ["bash", "my_entrypoint.sh"]
禁止される実行例：nginx & bash

リポジトリ内のすべてのスクリプトを調べ、無限ループを実行していないことを確認してください。
禁止されるコマンドの例：「sleep infinity」「tail -f /dev/null」「tail -f /dev/random」。

Makefileを実行してください。

ボーナス

このプロジェクトのボーナスは、比較的単純な内容になっています。
追加するサービスごとにDockerfileを書く必要があります。そのため、各追加サービスは専用のコンテナで実行し、必要であれば専用のボリュームも用意します。

必須項目がすべて完全に完成している場合に限り、ボーナスを評価してください。
ここでいう「完全」とは、必須項目がすべて実装され、不具合なく動作することです。
必須要件をすべて満たしていない場合は、ボーナスを評価しません。

ボーナス項目

- Redisキャッシュを設定し、WordPressサイトのキャッシュを適切に管理する。
- WordPressサイトのボリュームを参照するFTPサーバー用コンテナを設定する。
- PHP以外の好きな言語で、簡単な静的Webサイトを作る。PHPは明示的に禁止されている。例として、自分の紹介サイトや履歴書のサイトが挙げられる。
- Adminerを設定する。
- 自分で有用だと考えるサービスを1つ設定する。口頭評価では、そのサービスを選んだ理由を説明する必要がある。

課題で認められたボーナスを実装している場合、1項目につき1点を加えてください。
追加した各サービスについて、正常に動作することと、実装が適切であることを確認・テストしてください。
自由選択のサービスについては、評価対象者が仕組みと有用性を分かりやすく説明する必要があります。

0点（不合格）から5点（非常に良い）の範囲で評価してください。
